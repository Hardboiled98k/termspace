派活

让一个 agent 去指挥另一个

目标可以在同一块画布上，也可以在你的另一台机器上。跨机走的是你已有的免密 ssh —— 不新开任何端口，没有新增的暴露面。

最后一条是刻意设计的：连接串只在主进程里流转，一个字节都不进终端。 agent 用得到这个数据库，但看不到密码。

派活的四道闸 →

t-4a2 — zsh
# 派给画布上另一个终端里的 agent
tb ask t-7k3 "把 auth 那块的测试补齐"

# 跨机器同理，走你已有的 ssh 别名
tb ask mac-mini:t2 "跑一遍完整回归"

# 让 agent 查生产库 —— 但它拿不到连接串
tb db prod "select count(*) from orders"

账号

同一条命令，两个终端登两个号

靠给每个终端注入不同的配置目录做到，不是靠反复登出登入。 凭证内容用系统钥匙串加密后落盘，界面层从设计上就拿不到值 —— 只拿得到有哪些变量名。

还能显式删掉某个环境变量：你 shell 里 export 的 API key 会被应用继承，让订阅号白开还产生账单。

立场

我们不说「军用级加密」

画布上所有终端和应用本身跑在同一个用户身份下。 任何已经能在你机器上执行命令的进程，都可以绕开这里的全部检查。

所以画布上的「连线即授权」和弹窗确认，是产品护栏，不是安全边界。 它防的是 agent 拿错账号、连错库、把活派到你没打算派的地方 —— 不防一个已经拿到你 shell 的攻击者。

这条写在文档里、注释里，也写在这。

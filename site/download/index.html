安装

三步

  • 1 · 打开 dmg，把应用拖进「应用程序」 标准流程，没有安装脚本，不需要管理员密码。
  • 2 · 第一次打开会问要不要装 hook 那是节点边框跟着 agent 状态变的数据来源 —— 它会往 Claude Code / Codex 的配置里加几行。 你可以拒绝，其余功能照常，只是没有状态灯。 之后随时能在设置里开关，卸载时会问要不要一并清掉。
  • 3 · 建第一个终端节点 工具栏加号。想让某个终端用特定的订阅账号， 先在设置里加一个凭证，再从凭证节点拉一根线到它。

更新

之后怎么升级

应用自己检查

发现新版本会下好放着，然后等你点。 绝不自动安装，也绝不在退出时静默替换 —— 终端里跑着你的活，重启会掐掉正在进行的对话。

会话不会丢

更新重启后 tmux 会话还在，节点接回原来那个。 但 agent 的对话上下文是进程内的，重启就没了 —— 挑个空档再点安装。

更新链条到底保证了什么、不保证什么，逐条写在 安全模型 里。

卸载

删干净

删应用之前，先在设置里摘掉 hook。 设置 → 状态 hook → 卸载，它会从 Claude Code 的配置里移除 Termspace 加的条目。 首次写入时原文件已备份，就在同目录下。

然后把应用拖进废纸篓。还会剩下两样，都不影响系统， 想清干净的话手动来：本机数据目录（画布、凭证、滚动历史）， 以及后台还活着的 tmux 会话 —— 后者重启一次机器就没了。

没摘 hook 就删应用不会报错也不会卡住 —— Termspace 的 hook 脚本发现服务不在时会直接退出， 不影响你在别处正常用 Claude Code。

状态

它现在是什么成熟度

早期软件。功能是完整的、每天在真实使用中跑，但用户量还很小 —— 意味着还有没被踩到的边角。

它跑在你的开发机上、握着你的账号凭证、能往你的终端里敲字。 请按这个前提决定要不要用，以及先拿哪台机器试。 边界在哪写在 安全模型。
